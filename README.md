# APK TBuilder

Android-приложение, которое собирает APK прямо на телефоне: цепочка этапов с анимацией, встроенный терминал, фоновая сборка со службой переднего плана.

## Как получить APK самого приложения
1. Залей проект в GitHub-репозиторий.
2. Actions → «Build» запустится сам (или вручную). Готовый `apk-tbuilder-debug.apk` лежит в Artifacts.
3. Тег `v1.0` → APK появится ещё и в Releases.

Локально: `./gradlew assembleDebug` (JDK 17).

> `targetSdk = 28` сделан намеренно: Android разрешает запускать скачанные бинарники (aapt2) из каталога приложения только при targetSdk ≤ 28. Приложение подписано `app/debug.keystore` (пароль `android`) — это публичный отладочный ключ, для релиза замени его.

## Как это работает
Этапы по умолчанию: android.jar → SDK-утилиты → компиляторы → библиотеки → проверка окружения → подготовка → зависимости → манифест → aapt2 compile → aapt2 link → Kotlin → Java → dex → упаковка → подпись → проверка → готовый APK.
Этапы Kotlin, Java, dex и зависимости пропускаются, если в проекте нет кода и зависимостей.

**Что собирается на телефоне.** Приложения на Kotlin, Java и Jetpack Compose с зависимостями из Maven (Google Maven и Maven Central), ресурсами, ассетами и готовыми нативными библиотеками (`jniLibs/`). Подпись — схемы v1 и v2, собственный ключ RSA-2048 создаётся при первой сборке.

**Что ставится при первом запуске** (всё отмечено по умолчанию, потом интернет не нужен):
- `android.jar` API 35 и SDK-утилиты (aapt2, zipalign) — загрузка;
- **компиляторы** — встроены в приложение (`assets/jvm-tools.zip`, ~27 МБ): Kotlin 2.1 с плагином Compose, ecj (Java), d8. Они запускаются через `dalvikvm` (а если он недоступен — через `app_process`, куча до 256 МБ);
- **библиотеки** (~80 МБ) — Compose BOM 2024.12, Material 3, иконки, Activity, Lifecycle, Navigation, AppCompat, Material Components, ConstraintLayout, DataStore, OkHttp, Gson, Coil, корутины. Остальные зависимости проекта докачиваются при первой сборке и остаются в кэше (`files/m2`).

Зависимости читаются из `build.gradle(.kts)`, включая `platform("…bom…")` и версионный каталог `gradle/libs.versions.toml`. Версии без указания берутся из BOM; при конфликте побеждает наибольшая. AAR распаковываются, ресурсы библиотек компилируются один раз и кэшируются, манифесты библиотек сливаются в манифест приложения.

**Ограничения.** `kapt`/`ksp`/`annotationProcessor` (Room, Hilt и т. п.) на телефоне не выполняются — приложение предупредит. Код на C/C++ (`cpp/`) не собирается (нет NDK): берутся готовые `.so` из `jniLibs/`. Нужен Android 8.0+ (компиляторы собраны под API 26). Исходники Java компилируются с уровнем 1.8.

## Отладка
Журнал последней сборки сохраняется в `files/work/last-build.log`, ошибку шага можно скопировать кнопкой «Копировать» в карточке шага. В отладочной сборке можно запустить сборку без касаний: `adb shell am start -n com.builder.apkbuilder/com.builder.MainActivity --ez autobuild true --es project <имя>`; для импорта архива добавь `--es import <путь к zip в files/>`.

## Сборка самого приложения
Компиляторы собирает `tools/make-toolchain.sh` (JDK 17, curl, python3): результат — `jvm-tools.zip` для `app/src/main/assets/`. Готовый файл уже лежит в репозитории, пересобирать нужно только при смене версий Kotlin/ecj/r8.

## Свой проект из ZIP
Главный экран — большая кнопка «Собрать» по центру и кнопка «Выбрать ZIP с проектом» внизу. Архив можно:
- выбрать кнопкой (или пункт «Импортировать ZIP…» в списке проектов);
- открыть из файлового менеджера / мессенджера через «Открыть с помощью» → APK TBuilder;
- в терминале: `zip` (выбор файла), `import <путь> [имя]`, `pull <ссылка>`.

Приложение само находит `AndroidManifest.xml` (в корне, во вложенной папке репозитория или в `app/src/main`, папки `build/` игнорируются), делает его папку корнем проекта и переименовывает `java/` и `kotlin/` в `src/`. Нужны `AndroidManifest.xml` и обычно `res/`. Повторный импорт архива с тем же именем заменяет проект.

## Ход сборки
- Отмена: на узле остановленного шага рисуется синий крестик. При повторном запуске цепочка плавно откатывается снизу вверх: галочки и крестики стираются справа налево, заливка гаснет, соединители втягиваются, счётчик в заголовке убывает по шагам.
- Во время сборки под таймером раскрывается лента из трёх дуг: CPU и память дерева процессов сборки (само приложение, aapt2 и т. п.) и RAM системы. Данные берутся из `/proc` без Android API (`core/SysProbe.kt`); на новых Android чужие процессы недоступны, поэтому считаются только свои.

## Язык, тема и настройки
- **Язык** следует системе: русская локаль — русский интерфейс, любая другая — английский. В настройках можно закрепить «Русский» или «English». Тексты в коде русские; английский берётся из словаря `core/LDict.kt` (генерируется) и применяется только при показе, поэтому логика движка от языка не зависит.
- **Тема** следует системной: светлая или тёмная; закрепляется в настройках. Палитры — `Pal` в `Ui.kt`, терминал переключает и ANSI-цвета.
- **Настройки** — шестерёнка в шапке: язык, тема, «не гасить экран», уведомления о ходе и о результате, повторная установка компонентов, показать приветствие, удалить тулчейн, очистить историю.
- **Иконка** — робот с буквой T: адаптивная (`mipmap-anydpi-v26`) и PNG для старых версий; векторный логотип `ic_tbot` на приветственном экране.

## Первый запуск

Тёмный экран «Добро пожаловать» → выбор компонентов → установка. Страницы листаются наискосок. Список компонентов берётся из `assets.json` (и `toolchain/extra.json`), по умолчанию отмечено всё; «Выбрать всё» появляется, только когда ничего не выбрано. Если отметить не всё нужное, сборка может не пройти, но недостающее приложение предложит докачать при ошибке. Экран показывается один раз (флаг `onboarded`), и только если инструменты ещё не установлены.

## Умная докачка
Если сборка упала, приложение разбирает ошибку и **спрашивает**, что докачать (само ничего не качает):
- не хватает инструмента (`aapt2`, `android.jar`…) — предложит нужную загрузку;
- инструмент не запускается или `android.jar` повреждён — предложит скачать заново;
- в проекте нужен более новый API (`targetSdkVersion`/`compileSdkVersion` выше установленного android.jar, а aapt2 не нашёл ресурс `android:…`) — предложит `android.jar` нужного API (3–37, кроме 20);
- оборвалась загрузка тулчейна (сеть, 403/408/429) — предложит повторить; при 404 повтор не предлагается.

На экране «Сборка» появляется карточка-помощник: отметь, что скачать, и нажми «Скачать и собрать снова» — после загрузки сборка стартует сама. В терминале то же самое: `fix` (показать), `fix yes` (скачать и пересобрать).

Чтобы помощник умел докачивать твои инструменты, укажи в `assets.json` / `toolchain/extra.json` поле `provides` — какие инструменты даёт файл, например `"provides": ["d8"]`; для `android.jar` — ещё `"api": 33`.

## Gradle-проекты

При импорте ZIP читается `build.gradle(.kts)` модуля: `namespace`, `applicationId`, `versionCode/Name`, `minSdk/targetSdk`, зависимости и `manifestPlaceholders`. Этап «Манифест» переписывает `AndroidManifest.xml` (добавляет `package`, подставляет `${...}`) и передаёт версии в `aapt2 link`. Так собираются проекты, у которых в манифесте нет `package`. Если package нет и в Gradle, он подбирается сам: из объявлений `package …` в коде проекта, иначе `com.example.<имя проекта>`.

## Подпись

APK подписывается схемами v1 и v2 (нужна для targetSdk ≥ 30) и проверяется собственным верификатором.

## История
Вкладка «История»: график-«горы» числа сборок (24 ч / 7 дн / 30 дн) и красная линия ошибок. Веди пальцем по графику — кривая приглушается, выбранный отрезок загорается, всплывает подсказка с датой/часом, а число сверху показывает сборки именно за этот отрезок. Повторное касание снимает выделение. Ниже: успех, среднее время, пик, доли по проектам и последние сборки. Журнал хранится в `builds.jsonl` (отменённые сборки не считаются).

## Структура
- `core/` — чистая Kotlin/JVM-логика без Android: `Engine`, `Net` (загрузка, shell), `Zip`, `ApkSigner`, `Json`, `Ansi`.
- `History.kt` + `core/Stats.kt` — вкладка истории и подсчёт по часам/дням; `Hero.kt` — большая кнопка по центру; `ChainView.kt` — цепочка, которая рисуется по шагам; `TerminalView.kt`, `ResultCard.kt`, `Ui.kt`, `MainActivity.kt` — интерфейс на обычных View.
- `Android.kt` — платформа, `App`, служба, `ApkProvider`, установка/«поделиться»/экспорт.
- `assets/pipeline.json` — этапы сборки; `assets/assets.json` — загружаемые файлы; `assets/sample/` — пример проекта.

## pipeline.json
Поле `ops`: `download | shell | doctor | clean | pack | sign | verify | publish`.
Общие поля этапа: `title`, `requires`, `when` (`tool:x`, `exists:path`, `missing:path`), `optional`, `tip` (подсказка при ошибке), `cmd` (строка или массив для `shell`).
Переменные в shell: `TOOLCHAIN PROJECT BUILD OUT APP ANDROID_JAR AAPT2 ZIPALIGN D8 JAVAC` и `PATH`.
Своя версия: поменяй `version` — файл заменит копию в приложении (старая сохранится как `.bak`).

## Добавить свои инструменты
Файл `toolchain/extra.json` в каталоге приложения (формат как у `assets.json`): `url` или `urls` по ABI, `path`, `unzip`, `into`, `exec`, `check`, `sha256`.

## Терминал
`help`, `build`/`b`, `stop`, `doctor`, `tools`, `projects`, `use <имя>`, `pull <url> <имя>`, `apk`, `install`, `share`, `export`, `builds`, `pipeline`, `env`, `clear`, `cd`, `pwd`, `history`, `copy`, `reset toolchain --yes`.
Всё остальное идёт в `sh` (поддерживаются `|`, `;`, `&&`, `>`). Во время работы процесса ввод уходит в его stdin; кнопка `^C` останавливает команду вместе с дочерними процессами.
